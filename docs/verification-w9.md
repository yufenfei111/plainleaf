## 二、主题与外观走查

- [ ] **主题三模式切换**：设置页「外观」→ 主题模式分别点 跟随系统 / 浅色 / 深色，整 App 立即生效（不重启）。
- [ ] **跟随系统时手动改系统外观**：把手机系统切到深色/浅色，回 App 看是否自动跟随（需系统外观变化后回前台，注意进程被回收重拉的情况）。
- [ ] **强调色 5 色切换**：依次点 青竹 / 黛蓝 / 陶土 / 藤黄 / 墨紫，主色点缀全局生效——
      FAB、主按钮（如「开始导入」）、选中描边/对勾颜色随之变化。
      > 注意（读代码确认）：AppBar 背景是纸张色、**不被强调色重着色**；强调色只影响主色点缀，
      > 不要误判"AppBar 没变色=没生效"。
- [ ] **字体四档切换**：更小/标准/较大/超大 依次切换，可见正文字号变化，且布局不炸（不出现横向滚动/截断）。

## 三、持久化（最易翻车，重点）

- [ ] **重启 App 后主题偏好仍生效**：在设置页改主题模式/强调色/字体档，**完全退出进程再冷启动**，
      三项均回到上次选择（不是默默回落默认）。若回落默认=持久化路径异常（§四⑦ 风险）。
- [ ] **备份恢复后仍生效**：导出 `.plbk` → 改主题 → 从备份恢复 → 重启，主题随备份包一起还原
      （验证 settings_kv 确实进备份，而非 shared_preferences）。

## 六、Markdown 导入走查（Should 级）

入口：设置页「导入 Markdown（.md）」→ `/import` 粘贴页。

- [ ] **单条导入**：粘贴一条 `# 标题\n正文...` → 开始导入 → 提示"成功 1 条" → 回时间轴可见该条、正文可读（无 `#`/`*`/`` ` `` 等 Markdown 符号残留）。
- [ ] **多条导入**：粘贴多条、以单独成行 `---` 分隔 → 导入后时间轴出现多条（数量与 `---` 切分一致）。
- [ ] **含 `---` 的输入**：正文内想画分隔线会被当多条分隔符——确认这是预期行为（不残留 `---` 文本，而是被切成多条）。
- [ ] **空输入**：粘贴空/纯空白 → 点开始导入 → 提示"请先粘贴…"，不崩、不写库。
- [ ] **导入失败不白屏**：单条落库失败（如异常数据）不中断整批，给出明确错误提示而非崩溃。

## 八、环境要点（沿用 W5，换机器前必看）

1. **`flutter test` 必须去掉代理**：本机 `HTTP_PROXY` 会劫持测试进程与 `flutter_tester` 的本地
   WebSocket，报 `WebSocketException: Invalid WebSocket upgrade request`。执行：
   ```bash
   env -u HTTP_PROXY -u http_proxy -u HTTPS_PROXY -u https_proxy flutter test
   ```
2. **`flutter analyze` 在中文路径下必崩**：项目路径含中文时握手 JSON 百分号编码触发
   `FormatException: Unterminated string`。替代：`dart analyze lib test`，或 ASCII 路径副本里跑。
3. Windows 宿主跑数据层测试无需额外 sqlite3.dll（当前环境直接可用）；换机器报缺库时设
   `PLAINLEAF_SQLITE3_DLL` 指向 sqlite3.dll（见 `lib/app/providers.dart`）。
