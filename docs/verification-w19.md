## 一、本轮的起点：一个不会报错的洞

W17 交付后，多格式附件在链路上是通的：能导入、能落库、能备份、能恢复、能交给系统打开。
但展示层当时仍然是 W4 时代的形态 —— 六处各自写 `Image.file`，全部假设"附件就是图片"。

于是出现三个**不会报错、不会崩溃、测试也不红**的洞：

| # | 现象 | 根因 | 用户感受 |
|---|---|---|---|
| ① | 一条只挂着 PDF 的记录在时间轴上与"没有附件"完全一样 | `EntriesDao._rowsFor` 只查 `kind='image'` 选首图 | 以为附件丢了 |
| ② | 导出编辑后**再也看不到**自己挂了什么文件 | 详情页 `byEntry` 也只查图片 | 无法确认附件还在不在 |
| ③ | 同一条 PDF 在不同页面表现不同（文件图标 / 破图占位） | 六处各自判断"能不能渲染、失败显示什么" | 不知道哪个是对的 |
| ④ | 类注释写着"附件以清单形式列出"，实现里根本没有 | W5 起就如此，注释与实现不符 | 以为导出是完整的 |

这类问题的共同点是**唯一的拦截手段就是把"看得见"写成断言** ——
没有崩溃日志可查，也没有测试会因为"用户看不见"而变红。所以本轮以用例为核心交付。

---

## 二、四条改动：实现方式 / 影响范围 / 验证

### 1 · `AssetThumb`：把六处 `Image.file` 收口成一处

**新增** `lib/shared/widgets/asset_thumb.dart`。规则只有一条，且写在这一个文件里：

```
有可渲染位图 → Image.file（必带 cacheWidth）
没有位图     → 类型图标 + 扩展名徽标
图片渲染失败 → 破图图标（这是信息：图坏了）
非图片失败   → 类型徽标（这也是信息：不支持该格式）
```

**关键设计**：位图来源的挑选集中在 `AssetThumb.bitmapFor()`，而不是留给调用点：

| 类型 | 策略 | 理由 |
|---|---|---|
| 图片 | `thumb → 原图` | 历史数据（W4 期）没有 thumb，回退原图是唯一显示途径 |
| 其他 | **只认 thumb** | 回退原文件会把 PDF 二进制喂给图片解码器，每次重建稳定抛一次异常 |

> P1 补上 PDF 首页缩略图后，这里**无需改动**——有 thumb 就自动开始渲染。

**接入的六处**（原计划只盘到 4 处，实际实现时又找出 2 处）：

| 文件 | 位置 |
|---|---|
| `timeline_page.dart` | 卡片缩略图位（原 `_ThumbTile`，已改名为 `_ThumbSlot` 并新增分支） |
| `on_this_day_card.dart` | 那年今日行 |
| `gallery_page.dart` | 相册网格格子 |
| `calendar_page.dart` | 日历弹层行 ← **计划中漏掉的一处** |
| `entry_detail_page.dart` | 详情页横向翻页 |
| `editor_page.dart` | 编辑器附件条（原 `_FileBadge`，已删除） |

**刻意保留 `Image.file` 的三处**（并各自写明理由）：
详情页全屏查看、编辑器全屏查看、`photo_viewer_page.dart` 相册查看器 ——
它们**只可能收到图片**（数据源本身按 `kind='image'` 过滤），不需要类型分派；
且 `AssetThumb` 会把内容收进正方形盒，竖图在全屏下会被压得比满屏更小。

### 2 · 时间轴卡片：让"有附件"这件事可见

- `EntriesDao._rowsFor` **不再在 SQL 里过滤 `kind='image'`**：全取回来后按条目分组，
  一次查询同时算出「首图 / 附件总数 / 首个附件类型」。
- `TimelineRow` 与 `TimelineEntry` 相应新增 `attachmentCount` 与 `firstAttachmentKind`。
- 卡片缩略图位从两种分支变三种：
  有首图 → 位图；**有附件但都不是图片 → 附件类型图标（新增）**；无附件 → 记录类型图标。
- 附件数 > 1 时右下角出现数量角标。

**风险控制**：`firstAsset`（首图）的语义**完全没变**（仍只认图片），
因此「那年今日」「日历」两个消费方的行为零变化 —— 新增字段是纯增量。

### 3 · 详情页附件区：原名 + 大小 + 点开交给系统

`lib/features/detail/presentation/entry_detail_page.dart` 新增 `_AttachmentArea`：

- 只列**非图片**附件（图片已在上面横向翻页里展示过，列两遍是重复信息）；
- 每行：类型图标 + **原始文件名** + 大小 + 「用系统应用打开」；
- 点击走 `fileOpenerProvider`，失败只弹 SnackBar，不阻断页面。

新增 Provider `entryAttachmentsProvider`（走 `findAllAssetsByEntry`），
与既有的 `entryAssetsProvider`（走 `findAssetsByEntry`）**并存而非合并**：

> 前者是"这条记录带了哪些文件"，后者是"能翻看的图片"。
> 合并成一个带过滤参数的 Provider，会让每个调用点都要重新回答一次"我要的是哪种"。

### 4 · Markdown 导出：补齐附件清单（清掉注释债）

`MarkdownExporter._render` 现在真的会写附件段落 ——
W5 起类注释就这么写着，实现里一直没有（W17 已在测试注释里记明未擅自补功能）：

```markdown
## 附件
- [PDF] 作业第三章.pdf — `media/2026/09/<uuid>.pdf`
```

类型与文件名给人读，相对路径给脚本用（能据此从备份包里把文件捞回来）。
`exportAll` 用**一次查询**取全部附件再按条目分组，不逐条查。

## 三、顺带修掉的一处结构问题

`fileOpenerProvider` 原本注册在 `features/editor/presentation/providers/editor_providers.dart`。
详情页也要用它，若就地再注册一份，会出现**"测试只 override 了其中一个、另一个仍走平台通道"**
的隐蔽失败。已挪到 `lib/app/providers.dart`（与 `mediaStorageProvider` 同级的能力 Provider）。

测试无需改动：`w17_attachment_ui_test.dart` 本来就 import 了 `app/providers.dart`。

## 四、决策记录（都留了代价，不是"顺手做的"）

| 决策 | 取舍 |
|---|---|
| 时间轴卡片只显示**类型图标**，不显示文件名与大小 | 64dp 的格子里放不下「作业第三章.pdf」，截断成半截名字更难看。原名与大小放在详情页附件区 |
| 数量角标**只在 > 1 时**显示 | 缩略图本身已经说明"有一个附件"，那个「1」是噪声；从 2 开始才是"还有你看不到的东西" |
| 三处全屏查看**不换** `AssetThumb` | 它们只可能收到图片，不需要分派；正方形盒会把竖图压小 |
| `entryAttachmentsProvider` 与 `entryAssetsProvider` 并存 | 多一个 Provider，换来每个调用点不必重新回答"我要的是哪种" |
| 附件区放在正文**之后**、元信息之前 | "附件"是正文的附属；元信息是页面脚注 |

### 新增用例 `test/w19_asset_visibility_test.dart`（19 例）

| 组 | 守住的承诺 |
|---|---|
| `AssetThumb.bitmapFor` | 图片可回退原图、**非图片绝不回退**、空串与 null 等价 |
| 徽标与大小格式化 | 扩展名优先、无文件名退到类型中文名、1024 进制且 <10 保留一位小数 |
| 时间轴聚合 | 只挂 PDF 时数量=1 且首图为 null（**不能等同于"无附件"**）、混合时首图只认图片、软删不计入 |
| 详情页两条查询口径 | 图片查询只给图片、全部查询给全部且领域实体带原名与大小 |
| 详情页附件区（Widget） | 显示原名与大小、PDF 不被当图片渲染、点击交出的路径**拼上了支持目录**；只有图片时**不出现**附件区 |
| 时间轴卡片（Widget） | 只挂 PDF 时显示 PDF 图标而非记录类型图标；多附件显示角标 3、单附件不显示 |
| Markdown 导出 | 清单带类型/原名/相对路径；无附件时不写空标题；全部导出不串行 |
