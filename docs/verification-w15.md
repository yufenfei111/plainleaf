## 一、关于随需求附带的 `anime-4.5.0.zip`

包内是 **anime.js v4.5.0 的完整源码**（`src/easings/…`、`dist/bundles/anime.esm.js`、
100+ 个 `examples/*/index.html`），意图是"调用本地动画库做启动动画"。

**结论：不能直接使用。** 理由与替代方案：

| 项 | 说明 |
|---|---|
| 技术不兼容 | anime.js 是**浏览器**动画库（依赖 DOM 与 WAAPI）。素页是 Flutter/Dart，运行时没有 DOM 可操作 |
| 唯一"能用"的接法 | 内嵌 WebView 承载动画。代价：冷启动必须先初始化 WebView 引擎，与项目「冷启动 < 2s」的性能红线正面冲突；而收益只是一段不到一秒的过场 |
| 替代方案 | 原生 `AnimationController`，**缓动曲线对齐 anime.js 的定义**：`easeOutExpo` 与 `cubicBezier(0.22, 1, 0.36, 1)`（anime v4 的 cubic-bezier solver 同参数） |
| 素材是否浪费 | 没有。曲线参数直接沿用，动效语言与那份素材一致，后续要调手感也有对照基准 |

## 二、四项改动：实现方式 / 影响范围 / 验证

### 需求 1 · 启动进入动画

**实现方式**
- 新增 `lib/app/splash_transition.dart`：单个 `AnimationController`（880ms）驱动三段
  `Interval` —— 标记入场合（0–520ms，`easeOutExpo`，缩放 0.86→1 + 淡入）、
  名称入场（123→537ms，`cubicBezier(0.22,1,0.36,1)`，上移 14px + 淡入）、过场层退场（616–880ms）。
- 标记用 `CustomPaint` 纯几何绘制（一张带文字的纸页），**不引入图片资源**，因此不动 `pubspec` 的 assets。
- 接入点：`lib/main.dart` 的 `MaterialApp.builder`，层级为
  **启动过场 → 应用锁 → 路由内容**（过场在最外层，锁屏才不会在过场底下"闪一下"）。
- 无障碍：系统开启「减少动态效果」时**立即完成**，不播任何过渡。

**影响范围（这是本轮最关键的约束）**
- `child` **始终在树中**、不做布局变换 → 所有 `find.*` 断言照常命中；
- 过场层是 `IgnorePointer`（点击穿透）→ 所有 `tap` 断言照常命中；
- 动画完成后 `setState` 直接返回 `child`，**不留常驻 ticker** → `pumpAndSettle` 能立即静止
  （项目在 W10/W13 被"常驻动画拖死整套测试"坑过两次）；
- 过场里那两个字用 `RichText` 而非 `Text`，连 `find.text` 都不会多出候选。
- **结论：173 条既有用例不需要为这层视觉过渡做任何改写**（已由全量回归证明）。

**验证**：`test/w15_splash_test.dart` 5 例（穿透 / 静止 / 可关闭 / 无障碍 / 不干扰 find）。

### 需求 2 · 笔记多选 + 按条件筛选批量选择

**实现方式（自下而上四层）**

| 层 | 文件 | 内容 |
|---|---|---|
| DAO | `lib/core/db/daos/entries_dao.dart` | `selectIdsByFilter`（**不带分页 limit** 取全部匹配 id）、`softDeleteMany`、`setPinnedMany`，后两者单事务包裹 |
| 领域/数据 | `.../domain/repositories/timeline_repository.dart`、`.../data/timeline_repository_impl.dart` | 三个方法贯通；异常统一包成 `DatabaseException` |
| 状态 | `.../presentation/providers/note_selection.dart` | `NoteSelection`（active + id 集合）+ 控制器：`enter/start/toggle/selectAll/clearAll/exit` |
| 门面 | `.../presentation/providers/timeline_providers.dart` | `TimelineActions.idsMatching / deleteMany / pinMany` |
| UI | `.../presentation/timeline_page.dart` | 筛选条右侧「多选」入口；选择模式下**同一位置换成工具条**（已选 N / 全选 / 批量菜单 / 退出）；卡片左滑出勾选圈并整卡描边；长按 = 进多选、再长按 = 退出 |

**三个刻意的设计决定**
1. **「全选」取的是该筛选条件下的全部记录**（`selectIdsByFilter`），不是屏幕上已加载的几十条。
   若按已加载的选，用户以为全选了、实际漏掉看不见的那部分，接着一点删除就出事——
   这是最危险的一类静默错误。提示文案也会写清"已按当前筛选选中 N 条记录"。
2. **筛选条件一变就清空已选**（`ref.listen` 监听 `timelineFilterProvider`）。
   否则"换筛选 → 点删除"删掉的是用户当前完全看不到的记录。宁可让他重选一次。
3. **原长按菜单没有丢**：它搬到了卡片右侧的「更多」按钮（`entry-more-<id>`）。
   长按这种隐藏手势本来就不适合承载唯一入口；现在单条操作更显眼，批量操作另有一套。

**影响范围**
- 卡片 `onTap` 只在选择模式下改变语义，其余情况仍是进详情；
- 新增「更多」图标按钮会占一点卡片宽度（`IconButton` 默认 48dp 触控区，未压缩到不可点）；
- 批量删除只做**软删**（进回收站，30 天可恢复），沿用数据红线，未引入物理删除路径；
- 未改 `watchTimeline` 行为，时间轴分页语义不变。

**验证**：`test/w15_selection_test.dart` 8 例 ——
批量软删的条数/FTS 同步/回收站可见、幂等性、空列表安全、批量置顶、状态机、**筛选变即清空**、
页面入口与工具条切换。

### 需求 3 · 相册图片保存到本地

**实现方式**
- 新增 `lib/core/media/image_saver.dart`：抽象 `ImageSaver` + 三个实现
  - `GalleryImageSaver`：Android/iOS 走 `gal` → **写进系统相册**。
    "保存到本地"在这两个平台上唯一符合直觉的含义就是"出现在系统相册里"；
    若仅复制进 App 私有目录，用户打开系统相册根本找不到，等于没保存。
  - `DesktopImageSaver`：桌面没有"系统相册"概念 → 落到「下载」目录，**重名自动加序号**
    （`a.png` → `a-1.png`），绝不覆盖用户已有文件；提示里给出完整路径。
  - `RecordingImageSaver`：测试用，只记账不触盘。
- `defaultImageSaver()` 按平台选实现，UI 不关心自己跑在什么系统上。
- 入口：全屏查看器右上角「保存到设备」（`lib/features/gallery/presentation/photo_viewer_page.dart`，
  该页由 `StatefulWidget` 改为 `ConsumerStatefulWidget` 以便注入）。
- **保存的是原图**（`asset.relPath`），不是 medium/thumb —— 给用户一张缩略图是残次品，
  而他很难当场察觉。原图缺失时明确提示，不做"悄悄存个缩略版"。
- 平台错误翻译成人话：`accessDenied` → 引导去系统设置；`notEnoughSpace` → 空间不足；
  缺插件 → "当前环境不支持保存到系统相册"（而不是把 `MissingPluginException` 甩出去）。
- `AndroidManifest.xml` 增加 `WRITE_EXTERNAL_STORAGE` 并**限定 `maxSdkVersion="29"`**
  （Android 10 以下才需要；29+ 走 MediaStore 分区存储，不给权限——最小权限原则）。

**影响范围**
- 该页的既有注释写着"交互保持克制：只有翻页/缩放/关闭，不做分享、保存、编辑"（W11 决策），
  本轮**按使用者要求推翻了它**，注释已同步改写并注明理由，避免后人误判为随意加功能；
- 新增依赖 `gal ^2.3.0`（仅移动端生效；桌面路径零新依赖）；
- 相册网格的点击/长按行为**未改动**。

**验证**：`test/w15_save_test.dart` 5 例 —— 内容完整复制、重名不覆盖、缺插件时的可读失败、
假实现不触盘、查看器把**原图路径**交给保存器。

### 需求 4 · 布局观感升级

**做了两处有明确收益的改动（刻意收敛范围，不做"为改而改"）**

1. **设置页分组卡片化**（`settings_page.dart`）
   - 之前是「一条 ListTile + 一条 Divider」的长流水，十几个条目平铺、没有层级，
     找一个开关只能靠往下扫。
   - 现在收进 4 张分组卡：**外观 / 数据与导出 / 查找 / 安全**（云备份自带卡片保持原样），
     每组有 `titleMedium` 小节标题。条目文案与顺序一字未动。
2. **时间轴卡片缩略图 52 → 64**（`timeline_page.dart`）
   - 52 在 3x 屏上只有 156 物理像素，照片内容基本看不清，用户得点进去才知道是哪张；
   - 64 是"能认出画面"的最小档，卡片高度只多 12，一屏仍放得下三张；
   - 圆角随之 12 → 14，与设置页卡片视觉语言一致。

**影响范围**
- 纯视觉层改动，不涉及数据、路由、状态；
- 已确认既有测试**没有**对 `Card`/`ListTile`/`Divider` 数量或尺寸做断言
  （`search_page_test` 的 `ListTile` 断言在搜索页，与本轮无关）；
- 视觉最终效果**需要真机确认**（见第六节）——这类改动无法靠单测证明"更好看"。

## 六、真机走查清单（**未做**）

1. **启动过场**：冷启动观感是否流畅；到达主界面总耗时是否仍在 2s 内；
   开启系统「减少动态效果」后应直接进主界面。
2. **保存到相册**（必须真机）：全屏看图 → 点右上「保存到设备」→ 打开**系统相册**确认能看到该图；
   断网/飞行模式下也应成功（不依赖网络）。Android 10 以下会弹存储权限。
3. **多选**：长按卡片进多选 → 勾选若干 → 批量置顶 / 移入回收站 → 去回收站确认能恢复。
4. **按筛选全选**：选一个笔记本筛选 → 「全选」→ 提示的条数应与该笔记本实际条数一致
   （注意时间轴只显示前几十条，提示条数通常会大于屏幕上的数量，这是预期）。
5. **布局观感**：时间轴卡片缩略图是否更易辨认；设置页分组是否更容易找到入口；
   深色模式与字体放大档位下均需过一遍。
