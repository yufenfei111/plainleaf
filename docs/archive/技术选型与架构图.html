二、系统分层架构（示意）

轻量 Clean Architecture：上层只依赖相邻下层的抽象，数据源可在本地与 WebDAV 远端之间替换，UI 不感知数据来源。

① 表现层 Presentation Page / Widget —— 只负责渲染与交互
时间轴首页图文编辑器 相册网格学习（待办/计时/统计） 笔记本/标签日记与日历 搜索我的/设置
▼ 只通过状态读写，不直接碰数据库
② 状态层 State flutter_riverpod：Notifier / Provider / 响应式 Stream
EntryNotifierGalleryProvider StudyTimerNotifierSearchQuery SyncStateProviderSettingsProvider
▼ 调用用例 / 仓库接口
③ 领域层 Domain 纯 Dart，无框架依赖，可单测
实体：Entry / Asset / Notebook / Todo / StudySession Repository 抽象接口同步合并(LWW) / 统计计算等用例
▼ 接口由数据层实现（依赖倒置）
④ 数据层 Data Repository 实现 + 多数据源
Drift / SQLite（结构化数据 + FTS5 全文检索） 媒体文件存储（原图 + 两级缩略图） KV / flutter_secure_storage WebDAV 远端数据源（V3 双向同步）
▼ 调用基础服务
⑤ 基础服务 Core 横切能力，被各层复用
图片管线（压缩/EXIF/Isolate） AES-GCM 加解密 备份与导出（zip/PDF/长图/Markdown） 后台任务与本地通知权限管理
写入链路：编辑器 → 图片管线转码 → Repository 事务写库（entries/assets/tags/FTS）→ Stream 自动刷新时间轴、相册、统计
同步链路：写库同时入 sync_queue → SyncWorker 打包 →（可选加密）→ WebDAV；恢复时按 uuid+version 合并
