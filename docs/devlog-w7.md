## 二、月分组（#21）

分组逻辑抽到 `domain/timeline_grouping.dart` 做成**纯函数**：
这是列表里最容易写错、又最该被单测的一段（跨月、跨年、置顶插入都要对）。

- 月 → 日 → 条目三层；月头带「N 条」；
- **置顶项单独成组排在最前**。原因：DAO 的 `orderBy` 是「置顶优先 + 日期倒序」，
  若直接按月切分，"置顶优先"会被月份打碎成"9月置顶、8月置顶…"，语义就没了；
- 页面侧把分组摊平成 `_Row`（月头/日头/卡片）再交给 `ListView.builder`，
  保留 W6 的 thumb + `cacheWidth` 与视口缓冲。

## 三、筛选器（#21）

三维度：笔记本 / 类型 / 仅看置顶，可叠加。

关键决策：**过滤下推 SQL where，不做客户端过滤**。
`watchTimeline` 带 `LIMIT 100`，若先把 100 条捞出来再在 Dart 里筛，
数据量一大就会"筛选后只剩几条"——数据其实被截断在前 100 条里了。
所以 `TimelineFilter` 一路传到 DAO，翻译成 `where` 条件再 limit。

状态放在 `timelineFilterProvider`（`TimelineFilter` 不可变 + `copyWith`），
UI 改状态 → 流自动带新条件重查。筛选后无结果给独立空态（"没有符合条件的记录"），
和"一条记录都没有"区分开。

## 五、回收站（#23）

补齐删除侧：恢复 / 永久删除（二次确认）/ 清空回收站（二次确认）/ 剩余保留天数。

DAO 新增 `hardDelete` 与 `emptyTrash`，共用事务内 `_detachEntry`：

- `entry_tags`、`entries_fts`：物理删（纯索引数据，无软删语义）；
- `assets`、`todos`：**软删**（守住"删除一律软删"的数据红线，相册也不会出现孤儿图）。

顺序不能反——**drift 默认开外键约束**，子表行必须先处理，否则物理删 entries 会撞 FK。
